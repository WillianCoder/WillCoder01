Parte 1

A jornada: o que construímos

EtapaO que aconteceuO que você aprendeu
1. IdeiaUma plataforma de estudo por questões para o curso de formação de soldados, com Ciclo Básico e Ciclo Específico.Todo sistema começa por um problema real e por quem vai usá-lo (o aluno).
2. Conteúdo originalDecidimos escrever questões e resumos próprios a partir da lei, em vez de copiar materiais de terceiros.Direito autoral (Lei 9.610/98): o texto da lei é livre (art. 8º, IV); apostilas e questões de cursinhos têm dono.
3. CódigoO site foi construído em Next.js (React + TypeScript), com banco PostgreSQL acessado pelo Prisma.Um site moderno tem frente (o que o aluno vê) e servidor (regras, segurança, banco).
4. GitHubTodo o código ficou no repositório WillCoder01, com cada mudança em um Pull Request.Versionamento: nada se perde, tudo pode ser revisado e desfeito.
5. Testes automáticosCada PR roda testes (regras, questões, navegador) antes do merge.CI: o robô confere se nada quebrou antes de juntar ao código principal.
6. Rodar no notebookInstalamos Git, Node.js e VS Code; criamos o banco no Neon; configuramos o .env.Terminal, pastas, variáveis de ambiente e como ler mensagens de erro.
7. Banco de dadosRodamos migrate deploy (tabelas), db:seed (conteúdo) e admin:create (seu login).A diferença entre estrutura do banco e dados.
8. AuditoriaRevisamos segurança, desempenho e organização sem apagar nada.Mexer com cuidado: medir, testar e só então mudar.
9. Mais conteúdoO banco passou de 178 para 330 questões originais, e os resumos foram de 3 para 12.Conteúdo é o produto: o código é a vitrine.

Parte 4

Banco de dados: o que é, onde fica e como mexer

O que é

Um banco de dados é um "arquivo inteligente" organizado em tabelas (como planilhas). Cada linha é um registro (um aluno, uma questão) e cada coluna é uma informação (e-mail, enunciado). O nosso é um PostgreSQL, hospedado no Neon.

As peças

PeçaPapelOnde fica
PostgreSQLO banco em si.Nos servidores do Neon (EUA).
NeonEmpresa que hospeda o banco na nuvem.console.neon.tech
PrismaBiblioteca que conversa com o banco pelo código (ORM).prisma/schema.prisma
Migrações"Receitas" que criam ou alteram tabelas, em ordem.prisma/migrations/
SeedCarga inicial de conteúdo.prisma/seed.ts + content/
String de conexãoEndereço + usuário + senha do banco, em uma linha..env → DATABASE_URL

Anatomia da string de conexão

postgresql://neondb_owner:SENHA@ep-xxxx.us-east-2.aws.neon.tech/neondb?sslmode=require
└── tipo ──┘ └ usuário ┘ └senha┘ └──────── servidor (host) ───────┘ └banco┘ └─ opções ─┘

sslmode=require obriga a conexão a ser criptografada. O pooler (-pooler no endereço) é um "porteiro" que reaproveita conexões; para criar tabelas (migrate), usamos o endereço sem pooler.

Três jeitos de mexer, do mais seguro ao mais arriscado

JeitoComoUse para
1. Painel do site/adminTudo do dia a dia. Fica registrado na Auditoria.
2. Prisma Studionpx prisma studioConferir e corrigir pontualmente.
3. Neonconsole.neon.tech → Tables / SQL EditorVer de qualquer lugar, backup (branch), trocar senha.

Tabelas principais

TabelaGuarda
UserAlunos e admins. A senha fica como hash, nunca em texto.
SessionQuem está logado e em qual aparelho. O token fica como hash.
Plan / Subscription / Payment / CouponPlanos, acesso de cada aluno, pagamentos e cupons.
Question / QuestionOption / QuestionAttemptQuestões, alternativas e cada resposta dos alunos.
MaterialResumos e PDFs.
AuditLogHistórico das ações dos admins. Nunca apague.
Regra de ouro: antes de editar direto no banco, crie um branch no Neon (uma cópia instantânea). Se algo der errado, você volta.

Parte 7

Segurança na prática

Situação realO riscoA lição
A senha do banco apareceu em um print.Quem vê o print pode ler e apagar todo o banco.Trocar a senha (Reset password) e não fotografar o .env.
Senha do admin digitada aparecendo na tela.Ficou visível no print.Use outra senha, longa e única, e um gerenciador de senhas.
Projeto dentro do OneDrive.A sincronização trava arquivos (EPERM).Projetos em pastas fora do OneDrive, como C:\Projetos.
Repositório público.Qualquer pessoa vê o código.Código pode ser público; segredos nunca.

O que o site já faz para proteger

  • Hash de senha (Argon2id): nem você consegue ler a senha dos alunos.
  • Sessão única: o login vale em um aparelho por vez.
  • Limite de tentativas: barra robôs que testam senhas.
  • Cabeçalhos de segurança (CSP, HSTS…): dificultam ataques pelo navegador.
  • Webhook assinado: só o Mercado Pago consegue liberar acesso.
  • Auditoria: registra o que cada admin fez.

Parte 9

Glossário de A a Z

TermoO que é, em palavras simples
Access TokenUma "chave de acesso" em forma de texto longo. Quem tem o token age em seu nome naquele serviço (o do Mercado Pago cria cobranças). Trate como senha.
AdminAdministrador: usuário com acesso ao painel /admin.
APIApplication Programming Interface. Uma "porta de serviço" para um programa conversar com outro. O site usa a API do Mercado Pago para criar pagamentos.
API KeyChave que identifica quem está usando uma API (por exemplo, a do Resend).
Argon2idMétodo moderno de transformar senhas em hash, lento de propósito para dificultar ataques.
Assinatura (HMAC)Um "lacre" calculado com uma chave secreta. O Mercado Pago assina cada aviso; o site recalcula e só aceita se bater. HMAC = Hash-based Message Authentication Code.
BackupCópia de segurança para recuperar dados.
BranchNo Git: uma linha paralela de trabalho. No Neon: uma cópia instantânea do banco.
Build"Montar" a versão final e otimizada do site.
CacheGuardar um resultado para não refazer o trabalho.
CIContinuous Integration: robô que roda os testes a cada mudança (GitHub Actions).
CommitUma "foto" salva das mudanças, com descrição.
CookiePequeno dado que o site guarda no navegador (o nosso guarda o login e o tema).
CRUDCreate, Read, Update, Delete: criar, ler, atualizar e apagar dados.
CSPContent Security Policy: regra que diz ao navegador de onde o site pode carregar código. Bloqueia scripts maliciosos.
CSVPlanilha em texto, com valores separados por vírgula ou ponto e vírgula (usada na importação de questões).
CriptografiaEmbaralhar dados para que só quem tem a chave consiga ler.
DeployPublicar o site em um servidor na internet.
DNSDomain Name System: a "agenda" da internet, que transforma bizudosalles.com.br no endereço do servidor.
DomínioO nome do site (bizudosalles.com.br).
e2eEnd-to-end: teste que usa o site de verdade, no navegador, como um aluno.
FrameworkEstrutura pronta para construir sistemas (o Next.js é um framework).
Git / GitHubGit é o programa de versões; o GitHub é o site que guarda os repositórios.
Hash"Impressão digital" de um texto: transformação de mão única. Não dá para voltar ao original, mas dá para comparar. Senhas e tokens de sessão ficam assim no banco.
HostO computador ou servidor onde algo está (o host do banco é o endereço do Neon).
HSTSRegra que obriga o navegador a usar sempre HTTPS no site.
HTTP / HTTPSProtocolo da web. O "S" significa conexão criptografada (segura).
JSONFormato de texto para dados: {"nome": "valor"}. Nossas questões ficam em JSON.
LGPDLei Geral de Proteção de Dados (Lei 13.709/2018): regras para guardar dados pessoais. O site tem "baixar meus dados" e "excluir conta".
localhost"Este computador". localhost:3000 é o site rodando no seu notebook, porta 3000.
MergeJuntar as mudanças de um branch (PR) ao código principal.
MigraçãoArquivo que cria ou altera tabelas do banco de forma controlada.
Next.jsFramework de sites baseado em React que roda no servidor e no navegador.
node_modulesPasta com as bibliotecas baixadas pelo npm. Pode ser apagada e baixada de novo.
ORMObject-Relational Mapping: tradutor entre o código e o banco (o Prisma).
PATHLista de pastas onde o terminal procura programas.
Pooling / poolerReaproveitamento de conexões com o banco. Melhora o desempenho, mas não serve para migrações.
Porta"Número da porta" de um programa no computador (3000 = site; 5432 = PostgreSQL; 5555 = Prisma Studio).
PostgreSQLSistema de banco de dados gratuito e robusto.
PR (Pull Request)Pedido para juntar mudanças ao código principal, com revisão e testes.
Rate limitLimite de tentativas em um período (8 logins errados em 15 minutos, por exemplo).
ReactBiblioteca para montar telas com componentes.
RepositórioA "pasta" do projeto no GitHub, com todo o histórico.
robots.txtArquivo que diz ao Google o que pode aparecer na busca.
SchemaDesenho da estrutura do banco (tabelas e campos).
SeedCarga inicial de dados no banco.
ServerlessModelo da Vercel: o servidor "liga" sob demanda, e você não administra máquina.
SessãoO "estar logado". Nosso site guarda um token aleatório no cookie e o hash dele no banco.
SQLLinguagem para consultar bancos de dados (SELECT * FROM "User").
SSL / TLSA criptografia por trás do HTTPS e do sslmode=require.
String de conexãoLinha com tipo, usuário, senha, servidor e banco (ver Parte 4).
TerminalJanela onde se digitam comandos (PowerShell, Command Prompt).
TokenTexto secreto que prova uma permissão ou identidade. Há tokens de acesso (APIs), de sessão (login) e de redefinição de senha (link de uso único).
TypeScriptJavaScript com "tipos", que aponta erros antes de rodar.
Variável de ambienteConfiguração lida pelo programa fora do código (as linhas do .env e da Vercel).
Webhook"Aviso automático": um serviço chama uma URL do seu site quando algo acontece (pagamento aprovado).
2FAVerificação em duas etapas: senha + código no celular.
