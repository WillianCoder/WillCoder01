1. Abrir o projeto e o terminal

  1. No VS Code: Arquivo → Abrir Pasta… e escolha WillCoder01\PROJETOS\bizu-do-salles.
  2. Abra o terminal: menu Terminal → Novo Terminal (ou Ctrl + ').
  3. Se o PowerShell bloquear scripts, clique na setinha ao lado do + do terminal e escolha Command Prompt.

4. Adicionar e remover: passo a passo

4.1 Questões

Uma questão (mais fácil): entre no site como admin, vá em Admin → Questões → Nova questão, preencha e salve.

Várias questões (arquivo):

  1. Em content/questoes/, copie um arquivo parecido e renomeie (por exemplo, sp-cesp-01-seguranca.json).
  2. Troque o conteúdo mantendo o formato abaixo. O code de cada questão precisa ser único.
  3. Rode npm test e depois npm run db:seed.
{
  "cycle": "SPECIFIC",           ← "BASIC" ou "SPECIFIC"
  "subject": "Disciplina",
  "topic": "Assunto",
  "state": "SP",                 ← apague esta linha para valer no Brasil todo
  "sourceLicense": "Questões originais Bizu do Salles.",
  "author": "Bizu do Salles",
  "questions": [
    {
      "code": "CESP-SEG-001",
      "difficulty": "EASY",      ← EASY, MEDIUM ou HARD
      "statement": "Enunciado…",
      "options": { "A": "…", "B": "…", "C": "…", "D": "…", "E": "…" },
      "correct": "C",
      "explanation": "Por que a C está certa (mínimo 20 letras).",
      "reference": "Art. 5º, inciso X"
    }
  ]
}

Também dá para importar CSV: Admin → Importar.

Remover uma questão: em Admin → Questões, abra a questão e mude o status para Arquivada. Assim ela some para os alunos, mas o histórico deles continua certo.

Apagar do JSON não tira a questão do banco: o seed só adiciona. Remova sempre pelo painel.

4.2 Materiais e resumos

Pelo painel: Admin → Materiais, para criar, editar ou despublicar.

Por arquivo: copie um arquivo de content/materiais/, troque title e body (aceita ## títulos, **negrito** e listas com -) e rode npm run db:seed. Com "free": true, o material fica liberado para todos.

4.3 Planos, preços e cupons

Tudo pelo painel: Admin → Planos e preços e Admin → Cupons. Não precisa mexer em código.

4.4 Usuários e acesso

Admin → Usuários: liberar ou estender um plano, bloquear, trocar o papel (ADMIN/EDITOR). Para criar um admin, use npm run admin:create.

4.5 Textos, cartões e perguntas frequentes

Abra src/config/site.ts.

  • Adicionar um cartão: copie uma linha { icone: …, titulo: …, texto: … }, e cole logo abaixo.
  • Adicionar uma pergunta frequente: copie uma linha ["pergunta", "resposta"],.
  • Remover: apague a linha inteira, incluindo a vírgula do fim.

4.6 Item do menu do aluno

Em src/app/app/layout.tsx, na lista NAV: cada linha é um item. Cuidado: a lista MOBILE, logo abaixo, usa as posições da NAV (NAV[0], NAV[9]…); se apagar uma linha, confira essas posições. Para acrescentar, a página precisa existir em src/app/app/NOME/page.tsx. Peça ajuda nesse caso.

4.7 Regras e números

Em src/config/regras.ts, troque só os números. Exemplos: diasValidade: 30 define quantos dias o aluno fica logado; gratisPorArquivo: 3 define quantas questões grátis cada arquivo novo libera.

7. Banco de dados: acessar, ver e editar

O banco é um PostgreSQL hospedado no Neon. O endereço e a senha dele ficam no arquivo .env, nas linhas DATABASE_URL e DATABASE_URL_POOLED.

Três formas de acessar (da mais segura para a mais arriscada)

FormaComoUse para
1. Painel do admin (recomendado)Entre no site com a sua conta admin e acesse /adminTudo do dia a dia: questões, materiais, planos, cupons, usuários, escolas. Fica registrado na Auditoria.
2. Prisma StudioNo terminal: npx prisma studio. Abre http://localhost:5555 com as tabelas em formato de planilha.Conferir dados, corrigir um campo pontual.
3. Console do Neonconsole.neon.tech → seu projeto → Tables (planilha) ou SQL Editor (comandos)Ver o banco de qualquer lugar, criar backups (branches), trocar a senha.

Tabelas principais

TabelaO que guarda
UserAlunos e admins (e-mail, nome, papel, estado). A senha fica embaralhada (hash); ninguém consegue lê-la.
PlanPlanos à venda (nome, preço em centavos, dias de acesso, ciclos).
SubscriptionO acesso de cada aluno: status (PENDING, ACTIVE, CANCELED, EXPIRED) e endsAt (até quando vale).
PaymentCada pagamento recebido do Mercado Pago (valor, status, data).
CouponCupons de desconto.
Question e QuestionOptionQuestões e alternativas.
QuestionAttemptCada resposta de cada aluno (base do Raio-X e do ranking).
MaterialResumos e PDFs.
AuditLogHistórico do que os admins fizeram. Nunca apague.

Editar ou acrescentar pelo Prisma Studio

  1. Rode npx prisma studio e abra http://localhost:5555.
  2. Clique na tabela (por exemplo, Subscription).
  3. Editar: dê dois cliques na célula, mude o valor e clique em Save 1 change.
  4. Acrescentar: botão Add record, preencha e salve.
  5. Remover: marque a linha e clique em Delete. Evite fazer isso: prefira desativar ou arquivar pelo painel.
Antes de editar direto no banco: faça um backup. No Neon, crie um Branch (uma cópia instantânea), ou rode npm run db:backup (precisa do pg_dump; no Windows, use o Branch do Neon). Nunca edite AuditLog, Payment nem a senha (passwordHash) de ninguém.

8. Pagamentos, acesso dos alunos e o seu dinheiro

O site não guarda dinheiro nem "saldo" de aluno. Funciona assim:

  1. O aluno escolhe um plano e paga no Mercado Pago (Pix ou cartão).
  2. O Mercado Pago avisa o site (webhook). O site confere a assinatura do aviso e o valor, e grava um Payment APPROVED.
  3. O acesso (Subscription) fica ACTIVE até a data endsAt.
  4. O dinheiro cai na sua conta do Mercado Pago.
Quero…Onde
Ver quanto recebi, sacar ou transferirApp ou site do Mercado Pago → Seu dinheiro / Atividade. É lá que fica o seu saldo real.
Ver quem pagouPainel /admin (visão geral) ou a tabela Payment no Prisma Studio
Liberar acesso de quem pagou por fora (Pix direto)Admin → Usuários → Pedidos aguardando pagamento → Confirmar pagamento e liberar. Só faça isso depois de ver o dinheiro no extrato.
Dar mais dias a um alunoAdmin → Usuários: liberar ou estender o plano. Fica registrado na auditoria.
Devolver dinheiro (reembolso)No Mercado Pago, na venda → Devolver dinheiro. Depois bloqueie ou encerre o acesso no painel.
Mudar preços ou criar cupomAdmin → Planos e preços e Admin → Cupons
Ligar o Mercado PagoNo .env: MERCADOPAGO_ACCESS_TOKEN e MERCADOPAGO_WEBHOOK_SECRET (veja docs/PAYMENTS.md)
Não mude status nem endsAt na mão pelo banco se puder fazer pelo painel: pelo painel fica registrado quem mudou e quando.

9. Segurança: como se proteger

O que o site já faz sozinho: senhas com Argon2id (não dá para descobrir), um aparelho por conta, limite de tentativas de login, verificação de acesso no servidor, cabeçalhos de segurança (CSP), conferência de assinatura e valor nos pagamentos, e auditoria das ações do admin.

O que depende de você: checklist

✔AçãoComo
☐Trocar a senha do banco (ela apareceu em um print)Neon → Roles → neondb_owner → Reset password. Depois atualize DATABASE_URL e DATABASE_URL_POOLED no .env (e na Vercel, se já tiver publicado).
☐Nunca enviar o .env para o GitHub nem mostrar em printEle já está no .gitignore. Antes de mandar um print, esconda senhas e chaves.

☐Poucos adminsDê o papel EDITOR para quem só cuida de questões.
☐Backupsnpm run db:backup toda semana. O Neon também guarda um histórico curto.

Se desconfiar de invasão: 1) troque a senha do banco e do admin; 2) troque as chaves do Mercado Pago; 3) veja Admin → Auditoria; 4) restaure o backup se algum dado sumiu.

10. Deixar o site online 24 horas de graça

Recomendação: Vercel (site) + Neon (banco). As duas têm plano gratuito, ficam no ar 24 horas, dão HTTPS e não dependem da sua luz ou internet. É o caminho mais seguro para começar.

  1. Crie a conta em vercel.com/signup entrando com o GitHub.
  2. Add New → Project → escolha o repositório WillCoder01.
  3. Em Root Directory, coloque PROJETOS/bizu-do-salles.
  4. Em Environment Variables, copie as linhas do seu .env (DATABASE_URL, DATABASE_URL_POOLED, APP_URL, as chaves do Mercado Pago…). APP_URL passa a ser o endereço da Vercel.
  5. Deploy. Em cerca de 2 minutos, o site estará em https://seu-projeto.vercel.app.
  6. A cada merge no GitHub, a Vercel publica sozinha.
  7. (Opcional) Domínio próprio (bizudosalles.com.br, cerca de R$ 40 por ano em registro.br): Vercel → Settings → Domains.

Montagem do software (resumo)

  1. Instale o sistema: Raspberry Pi OS Lite 64-bit (com o Raspberry Pi Imager) ou Ubuntu Server 24.04 no mini PC.
  2. Instale o Node.js 22 e o git; clone o repositório; crie o .env.
  3. Banco: continue usando o Neon (mais fácil) ou instale o PostgreSQL 16 no próprio servidor.
  4. npm install → npx prisma migrate deploy → npm run build.
  5. Deixe rodando sempre com o PM2: npm i -g pm2, depois pm2 start "npm start" --name bizu, depois pm2 startup e pm2 save. Assim o site religa sozinho se o servidor reiniciar.
  6. Coloque na internet sem abrir portas no roteador com o Cloudflare Tunnel (grátis). Ele dá HTTPS, esconde o IP da sua casa e protege contra ataques. É preciso ter um domínio no Cloudflare.
  7. Segurança do servidor: atualizações automáticas (unattended-upgrades), firewall (ufw enable), login SSH só com chave e backup diário do banco.
Minha sugestão: publique agora na Vercel + Neon (grátis e estável). Monte o servidor em casa como projeto de aprendizado e use-o como ambiente de testes. Se um dia ele estiver bem estável, você decide migrar.
